# U5.2 — Magica jailbreak

Removes the adb-root escalation path: no zygote preload, no isolated service, no boot receiver, no
`--magica` branch in ksud. `late-load` itself stays, because it is the LKM loading path and
unrelated to how the process got there. Maps to upstream `U5.2 magica` (`magica.rs` 172 lines)
plus the Manager's `magica/` package and `cpp/adbroot.cc`'s zygote half.

## Why

Magica is a no-flash bootstrap: with SELinux in permissive mode, it rewrote `ro.debuggable` and
`ro.adb.secure`, restarted adbd with `service.adb.root`, and then reached back over TCP to run
`ksud late-load` under full root. It shipped as an isolated zygote service plus a
`BOOT_COMPLETED` receiver, and ksud carried an `adb_client` git dependency purely to talk to adbd
over a loopback socket.

The fork does not need it. Loading `kernelsu.ko` is `late-load`'s job, and on this fork the module
is loaded through the normal LKM install path. Magica's whole contribution was a way to obtain root
*in order to* load the module — circular on any device where the fork is already installed, and on
the devices where it is not, it depends on permissive SELinux, which is a worse state than not
being rooted. It is also the largest remaining write-to-system-properties surface in the app.

`late-load` stays. So does `adb_root` as a kernel feature (`K5.4`, driven from the settings page
via `ksud feature set adb_root`) and `libadbroot.so`, which `ksud install` copies to
`/data/adb/ksu/lib/` and which is not Magica's.

## Sync risk

Upstream still ships Magica, so this is a recurring collision:

1. **AndroidManifest.xml.** Three attributes and components were removed from a file upstream
   edits often. A sync restoring them is harmless on its own — the classes are gone, so the build
   fails at merge rather than at runtime. That is the preferred failure mode and it is worth
   keeping.
2. **cli.rs LateLoad.** `--magica` and `--post-magica` are still declared. Upstream changing their
   behaviour applies cleanly into the ignore branches, so the flags would keep parsing and keep
   doing nothing. G1 greps for the `magica::run` call, not for the flag name.
3. **Cargo.toml.** `adb_client` is removed. An upstream commit adding a second consumer of it fails
   to resolve, which is loud and correct.
4. **applySideEffects().** The function now handles one setting. Upstream adding a third toggle
   there applies cleanly; removing the function entirely would not.

## Rollback

Revert this commit; `magica.rs`, the three Java classes, the manifest entries and the
`adb_client` dependency all return. Nothing was persisted on a device beyond the boolean
`auto_jailbreak` preference, which is now unread — a user who downgrades gets their previous
setting back, and one who upgrades simply never sees the switch. No ABI number was retired and no
feature id was reused.
